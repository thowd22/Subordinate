## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented sub-model as six modules: ids, sequence, track, marker, media, project, plus a crate-level codes module.

Design decisions:
- IDs are generated by a define_id! macro so all seven newtypes share one implementation: UUIDv7 (Uuid::now_v7), Copy/Ord/Hash, Display and FromStr as the canonical lowercase hyphenated string, and hand-written Serialize/Deserialize that use that string in every serde format (not just human-readable ones, which is what uuid's own serde impl would do). UUIDv7 over v4 so ids sort by creation time, which keeps golden-file diffs and map iteration stable.
- Parse failures are SubError with the new stable code model.invalid_id, carrying entity and value details; sequence-setting validation uses model.invalid_settings.
- No floats anywhere: Clip.source_range is a TimeRange, Gap.duration and the crossfade offsets are RationalTime, SequenceSettings.frame_rate is a Rational.
- Transition mirrors OTIO's in_offset/out_offset rather than a single duration, so a crossfade that is not symmetric around the cut stays exact in integers. Transitions occupy no track time.
- Track holds an ordered Vec<TrackItem> (Clip | Gap | Transition), matching OTIO's positional layout, so clip placement needs no separate start field.
- serde derives on the entity structs are deliberately NOT added here: they need sub-time to be serde-aware, and stable field ordering plus schema_version are TASK-3.4's acceptance criteria. Only the IDs are serde-enabled, which is what AC #1 asks for.
- Fields owned by later subtasks are left out on purpose and noted in the doc comments: per-clip parameters (TASK-3.2), media relative path/content hash/probe info (TASK-3.3), track mute/lock (TASK-4.3).

Verification (all run in this worktree):
- cargo test -p sub-model: 23 unit tests + 2 doctests pass. Covers UUIDv7 version and uniqueness, creation-time ordering, Display/FromStr round-trip, serde as a canonical hyphenated string, malformed-id rejection carrying model.invalid_id with entity/value details, resolution and sample-rate validation, default settings (1920x1080, 24 fps, 48 kHz, Rec.709), 29.97 staying exactly 30000/1001, transitions consuming no track time, bin tree search, and an assembled Project -> Sequence -> Track -> Clip/Gap/Transition tree.
- cargo fmt --all --check: clean.
- cargo clippy --workspace --all-targets -- -D warnings: clean (run with the scratchpad GStreamer pkg-config env so sub-media builds; exit code 0).
- Cargo.lock changed only by adding the sub-model dependency edges and uuid's getrandom feature edge; no new crates were introduced.
