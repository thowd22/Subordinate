## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Serde was not on the model yet, so this task added it: sub-time (Rational, RationalTime, TimeRange) and every sub-model type now derive Serialize/Deserialize/JsonSchema. Types with invariants (Rational, TimeRange, Resolution, SequenceSettings, Scale2, Opacity, GainDb, MediaPath, ContentHash) deserialize through a private repr and their own constructor, so a hand-edited or migrated file can never produce a zero rate, a negative duration or a path that escapes the project folder. Structs use deny_unknown_fields; enums are snake_case.

New module crates/sub-model/src/json.rs: SCHEMA_VERSION = 1, ProjectFile { schema_version, project }, to_json and from_json. to_json goes model -> serde_json::Value -> a recursive key sort -> to_string_pretty plus a trailing newline, so the bytes stay identical even if some crate in the build turns on serde_json/preserve_order. from_json reads schema_version first and refuses anything but the current version with model.unsupported_schema_version (details: schema_version, supported_schema_version); the older-than-current arm is where TASK-3.5's migration registry hooks in. Bad JSON or values the model rejects give model.invalid_project_file. Both codes are new in sub_model::codes.

docs/schema/project-v1.schema.json is generated by schemars (sub_model::json::schema_text) and committed with a docs/schema/README.md; the committed_schema_is_up_to_date test fails on drift and SUB_UPDATE_SCHEMA=1 regenerates it. File name carries the schema version so TASK-3.5 can keep older shapes beside it.

Validation: cargo fmt --all --check clean; cargo clippy --workspace --all-targets -- -D warnings clean (with the scratchpad GStreamer sysroot env for sub-media); cargo test -p sub-model -p sub-time green (63 + 17 unit tests, 4 + 4 doctests, including a populated-project round trip, byte-identical repeat saves, a recursive sorted-keys assertion, an integers-only assertion so no float reaches the file, and rejection of newer/older/missing schema_version and of malformed values).
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->

The schemars-generated schema is committed at docs/schema/project-v1.schema.json and kept in step by a test. Verified with cargo fmt --all --check, cargo clippy --workspace --all-targets -- -D warnings and cargo test -p sub-model -p sub-time, all clean.
