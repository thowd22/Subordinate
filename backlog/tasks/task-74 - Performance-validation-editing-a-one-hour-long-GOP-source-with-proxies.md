## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Add a one-hour 1080p long-GOP fixture (longgop_1080p_1h.mp4) to scripts/gen-fixtures.sh and gen-fixtures.ps1 behind a new --hour/-Hour switch, keeping the two scripts in sync.
2. Add a --proxy mode to bins/subordinate-bench: locate the hour fixture, generate or reuse an intra-only proxy through sub_media::Proxy, then measure playback and scrub on both the source and the proxy through the production decode and NV12 upload paths.
3. Count stalls: add an optional stall threshold to the playback measurement (one frame interval) and record how many timed frames overshot it, so 'no stalls over 5 s of playback' is an integer check.
4. Add peak-RSS sampling (VmHWM on Linux, unmeasured elsewhere) and a documented memory budget, defaulting to 2 GiB and overridable with --memory-budget.
5. Report a ProxySection in the JSON report with per-criterion verdicts; exit non-zero with a stable bench.* code when a measured criterion fails.
6. Unit tests for argument parsing, verdicts, stall counting, RSS parsing and JSON round-trip; run the mode on the generated hour fixture here (software decode, no GPU) and record the numbers plus the budget in docs/PERFORMANCE.md.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Environment: WSL2, no GPU, no hardware decode, GStreamer 1.24 from a user-local prefix (timecodestamper absent), so the hour fixture is generated by hand with the same pipeline the script records.

Implementation: subordinate-bench gained a --proxy mode (bins/subordinate-bench/src/proxy.rs) that locates the new one-hour fixture, makes or reuses an intra-only proxy through sub_media::Proxy, measures playback and scrub on both files through the production decode and NV12 upload path, counts playback stalls against one frame interval, and reads the process's peak RSS (bins/subordinate-bench/src/memory.rs, VmHWM on Linux) against a documented 2 GiB budget. Report gained a ProxySection with per-criterion verdicts; a measured run that misses a number exits non-zero with bench.proxy_below_target. scripts/gen-fixtures.sh and .ps1 gained a --hour/-Hour tier and the longgop_1080p_1h.mp4 pipeline.

Verification (2026-09-11): cargo fmt --all --check clean; cargo clippy --workspace --all-targets -- -D warnings clean; cargo test -p subordinate-bench green (61 unit tests plus av_sync_harness and the new proxy_harness, run both without fixtures, where it is a skipped section exiting 0, and with SUB_FIXTURES_DIR on the generated hour fixture, where it makes a real proxy and asserts the criteria fields and the four scenarios).

Measured run (release, whole hour fixture), recorded in docs/PERFORMANCE.md: source scrub 8.803 fps versus proxy scrub 299.274 fps against the 30 fps target; 0 of 125 timed playback steps over the 40 ms frame interval, slowest 2.437 ms, across 5 s of playback; peak RSS 514 MiB of the documented 2048 MiB budget. All three criteria PASS and the binary exited 0. Proxy: MJPEG 960x540, 90000 frames, transcoded in 72 s.

Caveat on AC 1 and its mid-range machine: this is WSL2 on a Ryzen 9 9900X with no GPU and no hardware decoder, so decode was avdec_h264 and the NV12 upload and YUV-to-RGB pass ran on Mesa llvmpipe. That is the slowest path the code has rather than a mid-range GPU machine, and it still cleared the scrub target by a factor of ten; a hardware row should be added to the table when the verify tasks run on GPU runners (TASK-116). The fixture itself was encoded by hand with the exact pipeline the generator now records, because this sandbox GStreamer prefix has no timecodestamper and the script preflight cannot run end to end here; CI regenerates fixtures from the script. Deliberately not wired into CI: the hour fixture costs about 15 minutes of encoding and 380 MB against an 11-minute Linux job, so --proxy is a by-hand run and docs/PERFORMANCE.md says so.
